# Semantic HTML

This example shows how to build a webpage using **semantic tags** instead of a page full of `<div>` elements.

### Concepts Covered

- `<header>` — top area of the page (logo, site title)
- `<nav>` — navigation links
- `<main>` — the main unique content (use only **one** per page)
- `<section>` — a group of related content with a heading
- `<article>` — content that makes sense on its own, like a blog post
- `<aside>` — secondary content, like a sidebar or a note
- `<footer>` — bottom area with contact or copyright info

### Why use semantic tags?

1. **Better meaning** — the code itself explains what each part of the page is for.
2. **SEO** — search engines understand the page structure better.
3. **Accessibility** — screen readers can jump between sections properly.
4. **Easier to style** — you can target `header` or `main` directly in CSS.

### How to view it

Open `index.html` in your browser. Then right-click → **Inspect** and look at the page structure.

### Try it yourself

Add a `<section>` for "Projects" between the skills and the contact footer. Give it an `id` and add a link to it inside the `<nav>`.
