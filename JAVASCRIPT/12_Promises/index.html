12. Promises and Async/Await

A Promise is an object that represents a value that is not ready yet. It will be either fulfilled (it worked) or rejected (it failed).

The three states of a Promise

  • pending — still working
  • fulfilled — finished successfully
  • rejected — finished with an error

1. Creating a Promise

new Promise(function (resolve, reject) {
    setTimeout(function () {
        resolve("the data");
    }, 1000);
});

2. Using a Promise (.then / .catch)

  • .then(value => {}) — runs when it succeeds
  • .catch(error => {}) — runs when it fails
  • .finally(() => {}) — runs either way

3. Callbacks vs Promises

A callback is a function passed to another function. Promises give you the same result but with cleaner syntax and real error handling.

4. Promise.all, race and chaining

  • Promise.all([...]) — wait for ALL to finish
  • Promise.race([...]) — use the FIRST one to finish
  • .then().then() — chaining, one step after the other

5. async / await

An async function always returns a Promise. Inside it, await pauses the function until a Promise finishes — without needing .then().

async function getData() {
    try {
        const value = await somePromise();
        // runs after the promise finishes
    } catch (error) {
        // runs if it failed
    }
}

Why does this matter? Anything that takes time (loading data from a server, a timer, reading a file) is asynchronous. Promises and async/await are how JavaScript waits for it without freezing the page.
